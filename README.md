# aziel-anchors

External witness and auditor for [aziel-runtime](https://github.com/AzielEliab/aziel-runtime) (specs `AZRT-ANCHOR-1.0`, `AZRT-AUDITOR-1.0`). Author: Aziel Eliab.

- `anchors/log.jsonl` — append-only, chained witness statements of the runtime's chain heads (`/v1/anchor/heads`) and checkpoint tips. Each statement is signed with Ed25519 (`keys/witness.pub`), timestamped by RFC 3161 (freetsa.org, token in `anchors/tsr/<n>.tsr`) and logged in Sigstore Rekor.
- `audits/log.jsonl` — append-only, chained audit receipts from a separate job with a separate key (`keys/auditor.pub`): re-verifies every witness signature, TSA token and Rekor entry, and checks the live runtime still holds every anchored head.

The private keys exist only as this repository's GitHub Actions secrets (`WITNESS_ED25519_PKCS8`, `AUDITOR_ED25519_PKCS8`). The runtime Worker has neither key and no write access here; it pins the public keys and only reads these logs. Fail closed: a missing, re-ordered, re-signed or mismatching statement is refused by the runtime's `GET /v1/anchor`.

Key history: the first keys (statements 1-2, audits 1-2; see `keys/epochs.json`) were generated on the operator's build machine and retired on 2026-10-11. The current keys were generated inside a GitHub Actions run (`rotate-keys`, run 38108699312) and sealed straight into the Actions secrets; no machine outside GitHub held them in the clear. Honest limits: the repository owner can still rotate secrets or rewrite git history (Rekor and the RFC 3161 tokens are the parts the owner cannot rewrite). GitHub schedules are best-effort (gaps of more than 15 minutes happen).

**Witness-key rotation (AZRT-WITNESS-ROTATION-1.0).** A later rotation is accepted only when the old witness public key (`keys/witness.pub`) and the operator root public key both have valid Ed25519 signatures over the canonical rotation body (`from_public_key`, `to_public_key`). The root pin is `keys/operator-root.json`. Its `public_key` is `null` in this repo, and `verifyWitnessRotation` then returns `WITNESS-ROTATION-NO-ROOT` for every document, including one that carries both signatures. An unsigned document is `WITNESS-ROTATION-UNSIGNED`. A document signed only by the old witness key is `WITNESS-ROTATION-OLD-ONLY`. Both valid signatures, against a configured root, are `WITNESS-ROTATION-OK`. `rotate-keys.yml` runs that check before it mints keys, and it deletes `rotation.json` when the generated witness public key is not the signed `to_public_key`. No private key and no new Actions secret are added. The historical epoch in `keys/epochs.json` is unchanged. A direct git edit of `keys/witness.pub` is still a commit the owner can make; this check is the rotation gate, not a branch-protection rule.

Verify a statement yourself: recompute `sha256(canonical JSON of statement)`, check the Ed25519 signature with `keys/witness.pub`, then `openssl ts -verify -data <statement bytes> -in anchors/tsr/<n>.tsr -CAfile keys/freetsa-cacert.pem -untrusted keys/freetsa-tsa.crt`.

## External heads (EXTERNAL-HEADS-1.0)

Each new statement also carries `external`: the godlock.uk ledger head (from `https://godlock.uk/verify`) and the Aziel Corpus ACT-RECEIPT tip (from `/v1/receipts`), read directly from those sites, not through the runtime. A head is recorded only when its source verifies it (`status: VERIFIED`, no errors, 64-hex head); otherwise the entry is `{ "anchored": false, "reason": ... }`. An empty corpus chain (all-zero tip) is never anchored. Tests: `node tests/external-heads.test.mjs`.

**Build identity (RIB-041, AZRT-BUILD-WITNESS-1.0).** Each new statement carries `build { git_sha, version_id, assurance, provenance }`. `git_sha` and `version_id` are still the runtime's own `/v1/anchor/heads` report, signed with the heads. `assurance.git_sha` and `assurance.version_id` are `self_consistent` when that report agrees with itself, `inconsistent` when `heads.git_sha` and `build.git_sha` disagree, and `absent` when the field is null. That copy is marked `self_consistent`. It is not given the label `verified`. `provenance` (AZRT-BUILD-PROVENANCE-1.0) compares the runtime's reported bundle digest (`build_attest.artifact_digest`) with a CI provenance attestation whose body is `bundle_sha256` plus `git_sha` (`CI_PROVENANCE_JSON`, or `CI_PROVENANCE_URL` when the inline JSON is unset). Both equal is `ci.status: "match"` and `bundle_digest_status: "ci_match"`. A differing digest or git sha is `mismatch`. With no attestation, CI stays `not_checked` and the bundle digest stays `self_consistent` (`bundle_digest_source: "runtime_self_report"`). The statement does not copy `heads.build_attest` onto `statement.build_attest`, so a self-report is not echoed back as a witnessed attestation. An optional Cloudflare version read (`GET /accounts/{account}/workers/scripts/aziel-runtime/versions/{version_id}`) runs only when the environment has `CLOUDFLARE_READONLY_TOKEN`. This repo does not define that secret, and `witness.yml` does not pass it, so the witness records `cloudflare.status: "disabled"`. A CI or Cloudflare match/mismatch is anchored even when heads did not move. A stable `not_checked` self-report is not, by itself, a new statement. A redeploy (new git_sha or version_id) is anchored even when no head moved, except a real flap: a build-only statement is skipped only when its version_id equals the build of the statement just before the newest one (A, B, then A again) AND the newest statement is less than 15 minutes old. An honest rollback to any older version, or to the previous one after 15 minutes, is anchored. During a fast A/B flap the runtime's build check may report a mismatch on some isolates until it settles. Older statements carry the build fields they were signed with and verify unchanged. This job appends to `anchors/log.jsonl`. It does not rewrite earlier lines. The runtime's `checkBuildWitness` still returns its own status `verified` when the newest statement's git_sha and version_id equal the live build; this repo records the self-report as `self_consistent` and does not change that runtime label. Tests: `node tests/build-identity.test.mjs` and `node tests/build-provenance.test.mjs`.

**Schedule and witness on deploy.** The witness cron is `*/15`, but GitHub runs scheduled workflows best-effort; this log shows gaps of about 2-7 hours. So that a fresh runtime deploy is witnessed promptly, the deploy side dispatches `witness.yml` through its existing `workflow_dispatch` trigger right after deploy (`aziel-runtime/scripts/trigger-witness.mjs`, needs a token with `actions:write` here). A changed build is anchored without `force`. The runtime's build check reports `pending` (503, never a pass) for up to 4 h after a deploy while it waits.

**Why statements 24-34 have `build.version_id: null`.** The witness copies `build` from `/v1/anchor/heads`. Until 2026-10-17 01:08 UTC the live runtime (cbb3509) predated aziel-runtime #286 and published no `build` object, so `buildOf()` fell back to the top-level `git_sha` and left `version_id` null (never guessed). The runtime now publishes `build.version_id`, and the next statement carries it. The run log prints a warning whenever `version_id` would be null (`buildSource()`; not signed into the statement).

**Receipt key guard (AZRT-KEYS-1.0).** Before signing, the witness compares the runtime's `receipt_key` with the newest key recorded in this log and fails closed with `RECEIPT-KEY-DROPPED`, `RECEIPT-KEY-CHANGED-UNRETIRED`, or `RECEIPT-KEY-MALFORMED` (a key seen for the first time must be `key_id: "ed25519:<64 lowercase hex>"` with a 43-char base64url 32-byte `public_key`). **While the guard alerts, the witness halts all anchoring:** no statement is written for any head, build, or external tip, and every run fails until the runtime publishes a valid key or lists the old key in `receipt_key.retired`. Gaps in the log during an alert are expected; they are the alert. Tests: `node tests/receipt-key-guard.test.mjs`.
